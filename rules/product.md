# Product Rules

- Keep the core SaaS action obvious and reachable quickly.
- Build the smallest complete commercial product, not the largest feature list.
- Never add a feature solely because a competitor has it.
- Avoid fake/demo-only functionality in production-facing flows.
- Prefer progressive enhancement over rebuilding stable functionality.

## Learned rules
- **Every public claim is true.** "Free", "no sign-up", limits, counts, prices and competitor figures must match real behavior or a live source. Derive counts from data, never hardcode them.
- **One source for capability claims.** Feature status, supported regions/markets and prices live in one module. Page copy, FAQ structured data and llms.txt read from it instead of restating it per page.
- **No fake proof or personas.** No invented authors, testimonials, counters or customer logos. Use a team byline and real countable numbers.
- **Improvement phases are a dependency chain.** Stop revenue leaks first, then automate fulfilment, then build trust, then grow. Do not pull growth work ahead of an unfixed funnel.
- **Regulated output waits for the owner.** Prices, tax/legal/financial rules and legal text go live only after a recorded owner approval (see rules/launch.md).
